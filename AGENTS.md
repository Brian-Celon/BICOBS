# Workspace Rules & Constraints

## Git Workflow & Push Policy
- **NEVER push to remote (`git push`) without explicit user consent.**
- You may stage (`git add`) and commit (`git commit`) locally when implementing features or checkpoints.
- You must **NEVER** run `git push`, `git push origin <branch>`, or any command that sends changes to a remote repository unless the user explicitly commands or asks you to push in that turn.
- If changes are committed and ready to be published, inform the user and ask for confirmation before pushing.
