# Dashboard Project Rules and Conversations

## Design & Development Rules

1. **Naming Convention:** All HTML IDs, classes, and other attributes must use **snake_case** (e.g., `dashboard_container`, `sidebar_menu`). This makes it easier to target and style specific elements.
2. **CSS Scoping:** All CSS specific to the dashboard must go into its designated file, `dashboard.css`. Only use other CSS files if the styling is global and meant to be shared across the entire website.
3. **Code Commenting:** Use proper, direct, and to-the-point one-line comments to describe what a section of code does (e.g., `<!-- main dashboard wrapper -->`). Do not add elaborate or overly fancy comments.
4. **Version Control & Pushing:** All Git commits and pushes must be done manually by you (the user). I will never automatically push changes to the repository.
